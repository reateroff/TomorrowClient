# TomorrowClient

Минималистичный VPN-клиент для Windows с четырьмя ядрами, встроенными прямо в
приложение: **sing-box**, **TodayCore**, **Xray** и **mihomo**. Импорт серверов
по ссылкам, подпискам и готовым конфигам, нодовый редактор маршрутизации,
живой счётчик трафика, тёмный интерфейс. Собран на Wails (Go + React +
TypeScript + Tailwind).

## Возможности

- Четыре ядра в процессе приложения, отдельных `.exe` нет:
  - **sing-box** 1.15 — туннель, DNS и прокси в одном экземпляре;
  - **TodayCore** — sing-box с XHTTP, VLESS Encryption и REALITY из Xray;
  - **Xray** 26 — эталонная реализация VLESS, REALITY и XHTTP;
  - **mihomo** (Clash Meta) — XHTTP, VLESS Encryption, AnyTLS и др.
- Режим «Авто» подбирает ядро под каждый сервер; ручной выбор помечает
  серверы, которые выбранное ядро не потянет
- Протоколы: VLESS (REALITY, Vision, XHTTP, VLESS Encryption), VMess, Trojan,
  Shadowsocks (включая 2022 и obfs/v2ray-plugin), Hysteria, Hysteria2 (со
  сменой портов), TUIC, WireGuard, AnyTLS, SOCKS5, HTTP
- Транспорты: TCP (и HTTP-обфускация), WebSocket, gRPC, HTTP/2, HTTPUpgrade,
  XHTTP, mKCP, QUIC
- Импорт: ссылки (по одной или пачкой), base64-подписки, конфиги sing-box
  (JSON) и Clash/mihomo (YAML) — и вставкой, и по URL подписки
- Маршрутизация в двух режимах:
  - **Easy** — список доменов, IP и приложений;
  - **Pro** — нодовый редактор: ноды доменов (suffix/точный/keyword/regex),
    IP, портов, приложений (по имени и пути), сети, протоколов, GeoSite и
    GeoIP соединяются проводами с действиями «Через VPN», «Напрямую»,
    «Блокировать»; порядок нод — приоритет, «Остальное» задаёт действие по
    умолчанию. Для прямых доменов DNS идёт напрямую, для заблокированных —
    отклоняется
- Параметры TUN: стек, MTU, IPv6, строгий маршрут, сниффинг, DNS (UDP, DoT,
  DoH, DoQ); локальная сеть всегда идёт напрямую
- Проверка серверов на выбор: GET или HEAD через прокси (доказывает, что
  профиль рабочий), TCP-рукопожатие или ICMP; адрес проверки и таймаут
  настраиваются
- Просмотр и правка сервера: форма для серверов из ссылок (ссылка
  пересобирается после правки), JSON — для серверов из конфигов
- HWID для панелей с лимитом устройств (Remnawave, Marzban): заголовки
  `x-hwid`, `x-device-os`, `x-ver-os`, `x-device-model` в запросе подписки.
  Включено по умолчанию; можно выключить или подменить любое значение, вплоть
  до маскировки под другую систему (macOS, Linux, Android, iOS)
- Уведомления на Sonner, автозапуск, сворачивание в трей, темы оформления
- Скрытый раздел для разработчиков (10 нажатий на логотип в «О приложении»)

## Архитектура

```
main.go                — точка входа Wails, окно, биндинги
app.go                 — API для фронтенда (профили, ядра, настройки, соединение)
dev_windows.go         — инструменты разработчика
internal/model         — общие типы (Profile, AppSettings, RouteGraph, Status)
internal/cores         — список ядер, что какое ядро умеет, автовыбор
internal/store         — персист профилей и настроек (JSON в %AppData%)
internal/link          — парсер share-ссылок
internal/sub           — подписки и импорт: ссылки, base64, sing-box JSON, Clash YAML
internal/singbox       — конфиг sing-box/TodayCore, туннель-фронт, маршруты Pro
internal/xray          — конфиг Xray
internal/mihomo        — конфиг mihomo
internal/vpn           — движок: запуск ядер, проверки серверов, трафик
third_party/todaycore  — TodayCore, пересобранный под своим module path
frontend/src           — React UI (Tailwind v4, lucide-react, Sonner)
```

sing-box и TodayCore поднимают туннель сами: TUN-адаптер `TomorrowTun`,
`auto_route`, DNS и маршруты в одном экземпляре. Xray и mihomo работают за
**фронтом**: туннель, DNS и маршруты держит sing-box, а проксируемый трафик
передаёт ядру через loopback-SOCKS со случайным паролем. Так правила
маршрутизации реализованы один раз для всех ядер. Сокеты Xray и mihomo
привязаны к физическому адаптеру, чтобы их трафик к серверу не заходил
обратно в туннель.

TodayCore — форк sing-box с тем же module path, поэтому рядом с sing-box он
не линкуется как есть. `scripts/sync-todaycore.sh` берёт sing-box той версии,
что в `go.mod`, накладывает изменения TodayCore трёхсторонним слиянием,
переименовывает модуль в `github.com/tumgovic/todaycore` и уводит его
protobuf-описания в пространство `todaycore.*` (иначе глобальный реестр
protobuf падает на дубликатах). Обновить TodayCore:

```bash
bash scripts/sync-todaycore.sh
```

Счётчик трафика читает байты адаптера через `iphlpapi.GetIfTable2`.

## Сборка

Ядро прячет целые группы возможностей за build-тегами, поэтому сборка **обязана**
идти с ними. Теги прописаны в `wails.json` (`build:tags`), так что `wails build`
и `wails dev` уже корректны:

```
with_gvisor      — сетевой стек gvisor для TUN
with_quic        — Hysteria, Hysteria2, TUIC
with_utls        — отпечатки uTLS и REALITY
with_clash_api   — нужен для перехвата логов ядра
with_wireguard   — WireGuard
```

Нужен Go 1.27 (его требует Xray-core 26.9.9). При `GOTOOLCHAIN=auto` нужная
версия скачается сама.

Голый `go build` без тегов намеренно падает с ошибкой (`buildtags_guard.go`),
чтобы не получить молча собранный клиент без REALITY, QUIC и WireGuard.

```bash
wails dev          # запуск в режиме разработки
wails build        # production-сборка в build/bin/
```

## Требования для запуска

Рядом с exe должен лежать `wintun.dll` — это единственный внешний файл: ядро
загружает его в рантайме, чтобы создать TUN-адаптер, а Windows ищет эту DLL
только в каталоге приложения. В git он не хранится:

```bash
bash scripts/fetch-wintun.sh
```

> Приложению нужны права администратора — оно создаёт сетевой адаптер и
> правит таблицу маршрутизации. Это зафиксировано в манифесте
> (`requireAdministrator`).

код должен оставаться открытым — выпустить на его основе закрытый продукт
нельзя.

Форк разрешён, но публиковать его нужно под своим названием и со своим

нельзя — это право даёт AGPL и, до неё, лицензия sing-box.

## Безопасность

Клиент направляет весь системный трафик в туннель. Адреса локальной сети
(RFC1918, loopback, link-local) всегда идут напрямую в обход VPN. Маршрутом до
самого прокси-сервера управляет sing-box (`auto_route` + `auto_detect_interface`),
поэтому туннель не заворачивает собственные пакеты. Loopback-вход Xray и mihomo
закрыт случайным паролем на каждое подключение, так что другие программы на
компьютере не могут использовать его как открытый прокси.
