# TomorrowClient

Минималистичный VPN-клиент для Windows на ядре **sing-box**, встроенном прямо
в приложение. Импорт серверов по share-ссылкам, живой счётчик трафика, тёмный
интерфейс. Собран на Wails (Go + React + TypeScript + Tailwind).

## Возможности

- Импорт профилей по ссылкам `vless://`, `vmess://`, `trojan://`, `ss://`,
  `hysteria2://`, `tuic://`
- Подписки (subscription URL): загрузка списка серверов и обновление по кнопке
- Ядро sing-box работает в процессе приложения — отдельного `sing-box.exe` нет
- Маршрутизация по правилам: домены, IP/CIDR и приложения; локальная сеть
  всегда идёт напрямую
- Живая статистика скорости и объёма трафика прямо со счётчиков WinTun-адаптера
- Кастомный DNS, автозапуск соединения, сворачивание в трей
- Frameless окно с собственным тёмным title bar
- Скрытый раздел для разработчиков (10 нажатий на название в «О приложении»)

## Архитектура

```
main.go              — точка входа Wails, окно, биндинги
app.go               — API для фронтенда (профили, настройки, соединение)
dev_windows.go       — инструменты разработчика (диагностика, эмуляция, сброс)
internal/model       — общие типы (Profile, AppSettings, Status)
internal/store       — персист профилей и настроек (JSON в %AppData%)
internal/link        — парсер share-ссылок
internal/sub         — загрузчик подписок (base64/plain список ссылок)
internal/singbox     — генератор конфига sing-box
internal/vpn         — движок: запуск ядра в процессе, счётчики трафика
frontend/src         — React UI (Tailwind v4, lucide-react)
```

Ядро линкуется в бинарник как библиотека (`github.com/sagernet/sing-box`) и
поднимается через `box.New` / `box.Start` внутри процесса приложения. Конфиг
генерируется тот же, что принял бы отдельный `sing-box.exe`, и передаётся
в память, а не через файл. Логи ядра попадают в UI через `PlatformLogWriter`.

sing-box создаёт WinTun-адаптер `TomorrowTun` и сам правит таблицу
маршрутизации (`auto_route`); счётчик трафика читает байты адаптера через
`iphlpapi.GetIfTable2`.

## Сборка

Ядро прячет целые группы возможностей за build-тегами, поэтому сборка **обязана**
идти с ними. Теги прописаны в `wails.json` (`build:tags`), так что `wails build`
и `wails dev` уже корректны:

```
with_gvisor      — сетевой стек gvisor для TUN (используется по умолчанию)
with_quic        — Hysteria, Hysteria2, TUIC
with_utls        — отпечатки uTLS и REALITY
with_clash_api   — нужен для перехвата логов ядра
```

Голый `go build` без тегов намеренно падает с ошибкой (`buildtags_guard.go`),
чтобы не получить молча собранный клиент без REALITY и QUIC.

```bash
wails dev          # запуск в режиме разработки
wails build        # production-сборка в build/bin/
```

## Требования для запуска

Рядом с exe должен лежать `wintun.dll` — это единственный внешний файл: ядро
загружает его в рантайме, чтобы создать TUN-адаптер, а Windows ищет эту DLL
только в каталоге приложения. В git он не хранится:

```bash
bash scripts/fetch-wintun.sh
```

> Приложению нужны права администратора — оно создаёт сетевой адаптер и
> правит таблицу маршрутизации. Это зафиксировано в манифесте
> (`requireAdministrator`).

## Безопасность

Клиент направляет весь системный трафик в туннель. Адреса локальной сети
(RFC1918, loopback, link-local) всегда идут напрямую в обход VPN. Маршрутом до
самого прокси-сервера управляет sing-box (`auto_route` + `auto_detect_interface`),
поэтому туннель не заворачивает собственные пакеты.
